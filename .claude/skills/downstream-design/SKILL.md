# 《下游》Downstream 视觉语言

这份规范描述的是**已经在代码里跑着的**系统，不是提案。改动界面前先读它，改完之后如果引入了新的视觉决定，回来更新它。

真实来源（有冲突以代码为准，然后回来修这份文档）：
- `src/visitor.css` — 游客壳（标题、过场、结算）的全部变量与字体
- `src/game-ui.css` — 关卡内 UI 的变量
- `src/game-mode.js` — 每一关的 `dressing.bg`（水体颜色）
- `src/experiment-config.js` — 鱼群颜色

---

## 一、这个项目的核心张力：暖色的纸，冷色的水

这是整套视觉里最重要的一条，也是最容易被无意破坏的一条。

**UI 是暖的**（近黑偏棕的底 `#0F0E0C`、骨色的字 `#DDD8CC`、琥珀色的强调 `#C4892A`），**水是冷的**（L1 `#071426`、L2 `#12324a`、L3 `#111c28`，全是蓝）。

界面像一层贴在冷水前面的**纸**——观察者的记录、标签、判词。水在纸后面自己活着。

所以：

- 新增 UI 元素时，颜色从**暖色那一组**取，哪怕它压在蓝色的水上面。不要为了"和水协调"去调一个蓝灰色的面板，那会让纸溶进水里，这层关系就没了。
- 需要一个冷色的时候，先问它是不是应该属于水而不是 UI。
- **一个具体的坑**：`game-ui.css` 里的变量叫 `--game-blue`，值却是 `#C4892A`（琥珀）。这是早期改色时留下的名字。不要看名字取色，看值。

## 二、颜色

### UI（暖）

| 变量 | 值 | 用途 |
|---|---|---|
| `--v-bg` / `--game-paper-solid` | `#0F0E0C` | 底 |
| `--game-canvas` | `#1a1815` | 抬起一层的面 |
| `--v-text` / `--game-ink` | `#DDD8CC` | 正文 |
| `--v-text-dim` / `--game-muted` | `rgba(221,216,204,0.68)` | 次要文字 |
| `--game-faint` | `rgba(221,216,204,0.55)` | 再次要 |
| `--game-rule` | `rgba(221,216,204,0.12)` | 分隔线 |
| `--game-rule-strong` | `rgba(221,216,204,0.3)` | 强分隔线 |
| `--v-accent` / `--game-blue` | `#C4892A` | 唯一强调色（琥珀） |
| `--game-rust` | `#c96a4e` | 语义色·警示 |
| `--game-green` | `#8fa65a` | 语义色·良好 |

次要文字一律用**同一个骨色加透明度**（0.68 / 0.55 / 0.3 / 0.12），不要引入新的灰。这是这套色显得"整"的主要原因。

语义色（rust / green）各配一个 `0.16` 透明度的软版本做底。**语义色不算强调色**，不要拿它们当装饰。

### 水（冷）

| 关卡 | 背景 |
|---|---|
| L1 匮乏年代 | `#071426` |
| L2 | `#12324a` |
| L3 | `#111c28` |

L2 明显比 L1、L3 亮——这是叙事，不是失误。

### 鱼

| 鱼群 | 颜色 |
|---|---|
| small 猎物 | `#e5a441` |
| medium 玩家 | `#4f9fcf` |
| large 捕食者 | `#c95252` |
| 浮游 | `#14532d` |

**橙 = 猎物、蓝 = 你、红 = 捕食者**，这三个是玩家全程都在读的语义。任何新场景里都不要给这三个颜色换含义。教学关的参照鱼因此特意用中性灰 `#9aa7b2`——它既不是猎物也不是捕食者，取决于你把自己调成什么。

### 用色的分寸

强调色只有琥珀一个，而且用得很省：标题的 BEGIN、当前选中项、需要指认的那一个数。**一屏上出现两处以上琥珀，多半有一处该降级成骨色。**

## 三、字体

### 字族

`Roboto Flex`，自托管可变字体，字重轴 100–1000，只装了 latin 子集（`src/visitor.css` 的 `@font-face`，`unicode-range` 限定）。**中文不走这个字体**，落到系统栈（PingFang SC 等），所以中英混排时字重和字距要分开考虑（见第六节）。

长段落的散文用 `Georgia, 'Noto Serif SC', serif`——项目里只有理念页这类需要"读"的地方用衬线。

### 字重与字距成反比

这是这套字最有辨识度的规则：**字号越大，字重越低、字距越紧；字号越小，字重越低、字距越宽。**

| 角色 | 字号 | 字重 | 字距 |
|---|---|---|---|
| 大标题 | `clamp(2rem, 5vw, 4.6rem)` | `'wght' 260` | `-0.035em` |
| 小标签（全大写） | `clamp(0.7rem, 1.4vw, 0.9rem)` | `'wght' 200` | `0.22em` |
| 主行动号召 | `clamp(0.95rem, 1.6vw, 1.25rem)` | `'wght' 550` | `0.34em` |

用 `font-variation-settings: 'wght' N` 而不是 `font-weight`，这样能取到 260、550 这种非整百的值——整个视觉的细腻感就在这里。

**主行动号召是唯一的例外**：字重 550（全场最重）、字距 0.34em（全场最宽）、还带一层琥珀辉光 `text-shadow: 0 0 18px rgba(196,137,42,0.4)`。一屏只该有一个这样的东西。

字号一律用 `clamp()`，不写死。

## 四、两个世界：正式关卡 vs 教学关

这是叙事结构，不只是分区。

**正式关卡 = 不可逆。** 深水、暖纸、每个选择都会乘进下一代的系数。玩家在这里付代价。

**教学关 = 安全试验。** 没有指标、没有输赢、失败不惩罚。玩家在这里只负责**看见现象**，不负责优化任何东西。

两者的视觉必须能一眼分开，而分开的方式本身就在讲主题：**从教学关跨进第一代时，如果光线沉下去，那一下不需要任何文字解释。**

教学关的具体配色目前是待定项（浅色实验室 vs 工程蓝图两个方向）。在定下来之前，任何教学关界面只要守住这条：**它必须读起来是"可复原的"，而正式关卡读起来是"记下来的"。**

教学关还有几条已经定死的规矩：

- **一个控件。** 一课只教一个变量，控件也只有一个。
- **三段可见。** 机制的分段（被吃 / 互不理睬 / 吃）直接画在轨道上，不藏起来让玩家猜。
- **数字是读数，不是输入。** 平时只显示状态，鼠标移上去才展开具体数值和当前关系。
- **不出现参数表。** 开发者面板那一整套右侧参数栏在教学关里必须不可见。
- **不能说谎。** 界面写"你吃它"，仿真里就必须真的吃。判定直接转发引擎的函数，不要在 UI 层另写一套阈值——两份实现只要在边界差一个浮点位，界面就会当着玩家的面说错话。

## 五、动效

词汇很小，用得很克制：

- `--vo-wipe-dur: 0.65s` — 擦除转场
- `--vo-iris-dur: 0.8s` — 虹膜张开（过场 → 调参）
- `--vo-quad: cubic-bezier(0.45, 0, 0.55, 1)` — 唯一的缓动曲线

**所有转场用同一条曲线。** 想加新动效时先问能不能用现有的三个之一表达。这个项目的动效之所以不廉价，是因为它少。

虹膜张开是留给**世界切换**的（过场进入可玩状态）。不要拿它做按钮反馈这种小事，那会稀释它。

尊重 `prefers-reduced-motion`。

## 六、中英双语

**默认英文，可切中文。** 语言开关在游客壳上；任何会把游客壳关掉的界面（比如教学关）必须自带一个切换，否则从链接直接进来的玩家切不了。

排版上要注意的：

- Roboto Flex 只装了 latin。中文落系统字体，**同样的 `wght` 数值在两种字体下观感不同**——中文那边通常显得更重。中英并置时不要指望一套字重值通吃。
- **字距对中文是负担。** 拉丁小标签的 `0.22em` 放到中文上会散架。中文标签的字距应该显著收窄（`0.1em` 左右）甚至不加。
- 中文没有大小写，所以 `text-transform: uppercase` 那一套层级信号在中文界面里是失效的——得靠字号、颜色、位置补回来。
- 关卡标题这类文学性文本（《共工怒触不周山》）中英差异极大，**不要假设两种语言的行数一样**，容器要能吃下换行。

## 七、结构与文案

- **编号只在真是序列时才用。** 标题菜单的 01–05 是可以的（它是一份清单）。不要为了装饰给并列的卡片编号。
- **分隔线优先于卡片。** 这套界面靠 `--game-rule` 的细线和留白分区，不靠圆角方块堆叠。加新面板时先试细线。
- **数字对齐用 `font-variant-numeric: tabular-nums`。** 任何会跳变的数值（体型、比值、倒计时）都要，否则宽度抖动。
- **文案从玩家那一侧写。** 玩家读的是"你吃它"，不是 `pursuit`。内部术语（pursuit / evade / peer / coefficient）永远不出现在玩家可见的界面上。
- 关卡的判词是作品的一部分，不是 UI 文案，不要为了排版去改它。

---

## 八、几条别踩的

- 不要因为"和水更搭"就把 UI 调成冷色。暖纸冷水那层关系是刻意的。
- 不要看 `--game-blue` 这个名字取色，它是琥珀。
- 不要引入第二个强调色。要区分状态就用语义色（rust / green），要降级就用骨色加透明度。
- 不要用整百字重。这套字的可变轴给了 260、550 这样的值，用 `font-weight: 300` 会立刻变平庸。
- 不要给教学关配一套"看起来更专业"的深色仪表盘。教学关和正式关卡长得像，是这套设计里最贵的错误——玩家会分不清自己在不在付代价。
